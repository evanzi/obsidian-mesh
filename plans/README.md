## Discussion items (no plan — need external input)

- **Token acquisition via Mesh app's LevelDB** (`src/mesh-auth.ts:50-103`):
  the plugin scrapes JWTs from the desktop app's Local Storage files. Works,
  and tokens are held in memory only — but it's fragile (breaks on any Mesh
  storage change) and is the first thing the Mesh team will react to.
  Raise directly with them: ask for an official token/OAuth device flow or
  a sanctioned local-app handshake. Not plannable without their answer.
- **Incremental sync**: every sync re-fetches full detail for every contact
  (N requests + 100ms delay each; auto-sync multiplies this). Ask the Mesh
  team whether the list endpoint supports `updated_since`/modified ordering;
  then plan a skip-unchanged strategy.

## Findings considered and rejected / deferred

- **PII cache in data.json** (`sync-engine.ts:114` stores every mapped field
  value per contact, unbounded, in `.obsidian/plugins/obsidian-mesh/data.json`):
  real but acceptable for a personal plugin whose vault already contains the
  same data; data.json is gitignored. Revisit (hash values, prune deleted
  contacts) before wide distribution.
- **esbuild ≤0.24.2 moderate advisory** (GHSA-67mh-4wv8-2f99, dev server
  only): one-line bump to `^0.25.0` in devDependencies; no plan needed.
- **Dead code** (`mesh-api.ts:201-203 getContactNotes`, `218-220 getSelf`
  never called): delete or keep as intended surface for a future
  notes-sync feature; one-liner, no plan.
- **Pagination trusts client `limit`** (`mesh-api.ts:176-186` advances
  `offset += limit` instead of following `page.next`): only bites if the
  server clamps limit; fold into any future API work.
- **`window.open` with frontmatter-sourced Mesh ID** (`main.ts:51`): host is
  fixed by the URL prefix; worst case is a garbage path on app.me.sh. Wrap
  in `encodeURIComponent` opportunistically; not worth a plan.
- **Auth-error detection via `error.message.includes("auth")`**
  (`main.ts:117`): brittle but currently correct (both auth throws contain
  "auth"); use a typed error class if auth code is ever reworked.
- **Settings tab uses `createEl("h2"/"h3")` headings** (`settings.ts:44,74,145`):
  violates Obsidian community-plugin guidelines (use `setHeading()`, no
  top-level plugin-name heading); fix if submitting to Community Plugins.
  Same for manifest id `obsidian-mesh` — ids containing "obsidian" are
  rejected by the community-plugin review.
